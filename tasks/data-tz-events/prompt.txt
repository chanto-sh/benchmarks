Product wants to know how people use the app in their own local time. events.csv has every tracked event with a UTC timestamp, and users.csv has each user's IANA timezone. Event types weren't normalized, so the same type can show up with different casing or stray spaces.

Please answer these in answers.json:

- "saturday_local_events": how many events happened on a Saturday in the user's own local time.
- "busiest_local_purchase_hour": the local hour of day (0-23, as an integer) with the most purchase events.
- "berlin_purchases_2026_03_29": how many purchases users in Europe/Berlin made on their local date 2026-03-29.

Daylight saving changes happen during this period, so please use the real timezone rules rather than fixed offsets.
